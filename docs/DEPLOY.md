# 🚀 Daily Impact Devotional — cPanel Deployment Guide

## ✅ Data Flow — Confirmed

Here's exactly how your data is stored:

### Devotionals
- **Storage:** Every devotional you add or import via the Dashboard is INSERTED as a **row in the MySQL `devotionals` table** — title, date, scripture, paragraphs, prayer points, author, and all.
- **No JSON files.** Unlike the old system that stored everything in a 2.5MB JSON file, each devotional is a properly indexed database row.
- **Bulk imports** (from DOCX via mammoth.js on the frontend) are sent as JSON to `POST /backend/api/devotionals.php?bulk=1` and saved as individual rows.

### Header Images
- **File:** When you upload a header image, PHP saves the actual image file to **`uploads/headers/{month}_{year}/`** on the cPanel filesystem.
  - Example: An image mapped to "July 20, 2025" goes to → `uploads/headers/july_2025/july_20_2025_header.jpg`
- **Database link:** The **file path** (e.g., `uploads/headers/july_2025/july_20_2025_header.jpg`) is stored in the **`header_mappings` table** alongside the `date_key` (e.g., "july 20").
- **Monthly folders are auto-created.** If July doesn't exist yet, PHP creates `uploads/headers/july_2025/` before saving the file.
- **Frontend loading:** The React app calls `GET /backend/api/headers.php`, which queries the database and returns the real file path — no base64, no localStorage nonsense. The image is served directly from cPanel's filesystem.

### Devotional DOCX Imports
- When you import a DOCX file via the Dashboard, the frontend uses `mammoth.js` to extract the text client-side, then sends the parsed JSON to `POST /api/devotionals/bulk`.
- To **keep the original DOCX file** on the server, upload it via the Dashboard → it gets saved to **`uploads/devotionals/{month}_{year}/`** and a reference is stored in the `uploaded_files` table.

### Bottom Line
> ✅ **Everything is in the MySQL database** — devotionals, headers, settings, foreword, donations, login logs, Telegram logs, mail queue.  
> ✅ **All image files are on cPanel's filesystem** — under `uploads/headers/{month}_{year}/` and `uploads/devotionals/{month}_{year}/`.  
> ✅ **No localStorage.** The only thing in localStorage is the theme preference (light/dark/auto) — that's a pure UI choice with no server data.

## ✅ PHP Requirements

Your cPanel server needs:
- **PHP 8.0 or higher** (the code uses `str_starts_with`, `str_contains`, named arguments)
- **Extensions:** `pdo_mysql`, `curl`, `fileinfo`, `mbstring`
- **Apache module:** `mod_rewrite` (almost always enabled on cPanel)

You can check/change these in cPanel → **Select PHP Version**.

## Step 2: Create a MySQL Database in cPanel

1. Open **MySQL Databases** in cPanel
2. Create a new database (e.g. `youruser_devotional`)
3. Create a database user (or use an existing one)
4. **Add the user to the database** with **ALL PRIVILEGES**
5. Note down:
   - Database name
   - Database username
   - Database password
   - Database host (usually `localhost` on cPanel)

## Step 3: Run the Installer

1. Visit **`https://yourdomain.com/install.php`** in your browser
2. Fill in the MySQL details from Step 2
3. Set your **Admin Email** and **Password** (the admin password for logging into the dashboard)
4. Click **Install Now**

**The installer will:**
- ✅ Create all database tables (settings, admin_users, devotionals, header_mappings, etc.)
- ✅ Write the config file (`config/db.php`) with your credentials
- ✅ Set up your admin account
- ✅ Create the `uploads/` directories
- ✅ Show a success screen

5. **IMPORTANT: Delete `install.php`** from your server after installation!

## Step 6: Set Up Telegram Cron (Optional)

The Telegram scheduler needs a cron job since PHP doesn't run persistently:

1. In cPanel, open **Cron Jobs**
2. Add a new cron job:
   - **Common Settings:** `*/10 * * * *` (every 10 minutes)
   - **Command:**
     ```
     curl -s "https://yourdomain.com/backend/api/telegram-cron.php?key=YOUR_SECRET_KEY" > /dev/null 2>&1
     ```
3. Replace `YOUR_SECRET_KEY` with a random string
4. Go to Settings → **Cron** in the Dashboard and add the same key as `cron_secret_key`

## Step 7: Build the React Frontend

The frontend is already wired to the backend — **no manual URL edits are needed**:

### 1. API base URL is centralized in `src/config/api.ts`
```typescript
// src/config/api.ts — single source of truth (no need to touch)
export const API_BASE = import.meta.env.VITE_API_URL || "/backend/api";
```
Every component imports this constant, so the whole app targets the PHP API at
`/backend/api/*.php` (e.g. `/backend/api/admin.php?action=check`,
`/backend/api/login-log.php`).

### 2. Auth uses PHP sessions
Login/logout/session-check all call `admin.php?action=login|logout|check` through
the `api()` helper in `src/lib/api.ts`. The server owns the session; the app
verifies it on mount via `action=check`.

### 3. Build and copy
```bash
npm run build
# Copy contents of dist/ into the archive root (same folder as .htaccess),
# alongside the backend/ folder
```

## Troubleshooting

| Problem | Fix |
|---|---|
| **404 on page refresh** | Make sure `.htaccess` is in your document root with SPA routing rules enabled |
| **API returns 500** | Check `config/db.php` has correct credentials. cPanel MySQL usually uses `localhost` |
| **CORS errors** | All API files include CORS headers — no extra setup needed |
| **File uploads fail** | cPanel may have file size limits. Check `upload_max_filesize` in PHP settings |
| **install.php not working** | Make sure your MySQL user has `CREATE DATABASE` privileges, or create the database manually first |
| **Login doesn't stick** | You updated the frontend auth check (Step 7.2) correctly? The app must call `/backend/api/admin.php?action=check` |
